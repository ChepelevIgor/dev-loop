# Dev Loop development

- Keep credentials, private project names, internal URLs and real user data out of code examples, tests and screenshots. Use neutral examples such as `TASK-12` and local fixtures.
- Run the tests relevant to each change. Validate packaging after changing manifests, bundled files or the release builder.
- Keep the portable, Claude and Codex manifest versions synchronized.
- Publish releases or replace public history only when the user requests it. Building a local archive does not publish it.
